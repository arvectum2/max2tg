# MAX2TG Personal UX P1.3 — поиск и история

Дата: 23.10.2026. Личная версия на Mac mini.

## Как использовать

- /find хлеб — найти сообщения в текущей теме MAX; в General — во всех подключённых темах.
- /findall договор — поиск во всех подключённых MAX-чатах.
- /find с:2026-10-01 по:2026-10-23 — только по датам включительно.
- /find хлеб с:2026-10-01 по:2026-10-23 — текст плюс даты.
- Даты и время интерпретируются по Москве (UTC+3).
- Искать дальше — вывести остальные результаты текущего окна и прочесть более старую страницу.
- Открыть — ссылка на уже существующее Telegram-сообщение, когда его MAX ID сопоставлен.
- /history в теме — ручной импорт старых сообщений MAX порциями по 20.
- /history reset — сбросить позицию ручного просмотра без удаления сообщений или outbox.
- Старая команда /search по-прежнему ищет людей, группы и каналы, не сообщения.

## Надёжность, приватность и границы

Поиск использует существующий MAX user WebSocket opcode 49 (CHAT_HISTORY),
а не неподтверждённый серверный полнотекстовый API. За один проход читается
не более 100 записей на чат, максимум 12 чатов; отображаются до 8
совпадений за экран. При большем количестве все результаты текущего
окна сначала показываются по кнопке, и только потом читается старое
окно. Дополнительные кнопки старых сеансов не могут сдвинуть новый поиск.

Поиск не пересылает старую переписку. Сведения результатов и фильтров
хранятся лишь в памяти пользовательской сессии Telegram. Временные
ссылки на медиа MAX, токены вложений, контакты и полные тексты не
пишутся в индекс или в логи. Оставляем только до 200 символов от
каждого найденного сообщения в памяти.

История догружается только после явного нажатия администратора в
корректной Telegram-теме. Используются существующие import_recent_history,
постоянный SQLite outbox и MAX↔TG mapping. Блокировка asyncio.Lock
общая с входящими live events и автоматической догрузкой.

Позиция ручного просмотра manual_history_from хранится в TopicStore
только как timestamp, сохраняется после полного подтверждения
доставки. При ошибке, неполной странице MAX или неопределённом
таймауте позиция не изменяется. Страницы перекрываются по времени
на 1 мс и дедуплицируются по MAX ID. Неразделимые страницы с
одинаковым timestamp останавливают просмотр вместо скрытого пропуска.
При удалении темы сохранённая позиция очищается.

Тексты поисковой выдачи, опубликованные в общей Telegram-супергруппе,
могут читать другие участники этой группы; запуск поиска, переключение
его страниц и импорт разрешены только администратору.

Это постраничный просмотр доступной MAX-истории, а не индекс
удалённых сообщений или полной Telegram-переписки. Настоящие
максимально старые MAX-чаты и сложные emoji-таймстемпы желательно
дополнительно проверить в изолированном тестовом аккаунте.

## Приёмка

tests/test_history_nav.py: фильтры, поиск в одном и нескольких чатах,
пагинация и большое число совпадений, ссылки на Telegram-сообщения,
HTML-escaping, отсутствие токенов MAX в выдаче, права администратора,
устаревшие кнопки, durable cursor после рестарта, ошибка загрузки
и отсутствие повторов. Полный pytest, compileall, pip check и diff check.

Перед установкой делаем резервную копию topics.json и согласованный
SQLite backup. После — проверка авторизации MAX, Telegram polling,
целостности SQLite, старых тем и message mappings.
