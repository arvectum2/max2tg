# P2.2b / P0.5 — coordinated stopped-runtime delivery-state backup

Base main 9d44266 (PR #23 merged). Canonical ROADMAP.md reviewed at that revision; original criteria and status unchanged. P2.2b and live P2.2c remain open.

`capture_delivery_state` acquires the independent backup lock, existing gateway runtime lock and every isolated worker lock in deterministic order before reading delivery data. A running gateway or worker causes immediate refusal; no process is stopped by the tool. Explicit external capsule set must match the central registry exactly, including inactive capsules, and each worker ACL must match its registered identity and forum. Caller must independently stop onboarding/provisioning and other registry writers (not covered by runtime locks). SQLite backup API creates standalone checked copies, JSON files are copied, all files are private and fsynced, staging is published to a new directory and only then anchored by the independent recovery manifest. Incomplete staging is removed; a complete copy left by an anchor-publication failure is not independently authorized. Existing snapshots are not overwritten. Dirty anchor and changed membership refuse capture unless applicable trusted reconciliation is provided. A verified snapshot can be materialized into a new private flat directory, byte-checked against the anchor; no in-place restoration or activation. Trusted single operator and non-hostile filesystem assumed.

Actual integration test uses central registry, SharedGatewayRuntime and two IsolatedWorkerRuntime instances with synthetic messenger boundaries. Delivers two messages each way, verifies capture refusal with gateway and then worker active, refuses partial tenant set, closes all runtimes, captures 11 delivery-state files (three central SQLite DBs and four files per worker), materializes fresh verified copies, confirms two ACKED ingress rows and both worker SENT receipt IDs. Repeated destination and dirty epoch denied. No MAX token, bot token, IPC key or browser profile copied by this delivery-state backup; credentials and keys need their separately protected retention. Message data in these files remain sensitive; encryption and independent secure retention required before production use. No automatic restore or live external send. 878 tests passed, 36 existing PTB warnings, targeted Ruff, runtime preflight and unchanged Spec Kit structural gate passed. No personal bridge changes.
