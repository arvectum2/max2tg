# MAX2TG P0.5 — испытания отказоустойчивости

Дата: 23.10.2026. Сбойные испытания проходят в изолированных временных
каталогах, без отправки сообщений реальным MAX/TG собеседникам.

## Матрица испытаний

| Сбой | Проверяемый результат |
| --- | --- |
| Аварийный выход отдельного Python-процесса, outbox SENDING | на новом старте UNKNOWN, слепого повтора нет |
| Аварийный выход до сетевого запроса | безопасное возобновление RETRY |
| Аварийный выход после первой части длинного сообщения | подтверждённый Telegram message ID сохранён, следующая часть UNKNOWN |
| Telegram RetryAfter / перезапуск SQLite | оставшиеся части досылаются, подтверждённые не повторяются |
| Telegram TimedOut | UNKNOWN остаётся после перезапуска, без повтора |
| SQLite BEGIN IMMEDIATE (второй процесс/соединение) | Telegram API не вызывается до успешной записи в outbox |
| MAX история больше лимита страниц | курсор не продвигается, BUDGET_EXCEEDED |
| Одинаковые timestamp на границе истории | перекрытие страниц, дедуп по MAX ID; без доказанной полноты курсор не продвигается |
| Ошибка догрузки после рестарта | warning переживает перезапуск и отображается как HISTORY_GAP в /status |
| Предыдущие тесты MAX disconnect, logout и Telegram polling | контролируемое восстановление и отсутствие drop_pending_updates |
| Безопасный перезапуск launchd | сохранились mappings, курсоры и SQLite, авторизация MAX и Telegram polling восстановлены |

## Найденная проблема

Ранее пагинация использовала min(timestamp)-1, из-за чего при совпадении
миллисекунд у нескольких сообщений на границе страниц некоторые ID могли
быть пропущены с ложным продвижением сохранённого курсора.

Теперь страницы перекрываются по timestamp (min(timestamp)+1), совпавшие
ID дедуплицируются. Если API возвращает полностью одинаковые timestamp,
без дополнительного offset/ID курсора доказать полноту нельзя. В этом
случае сохраняется предупреждение TIMESTAMP_TIE и прошлый checkpoint,
вместо необоснованного объявления об успешной доставке.

Другие сохраняемые причины проблем: RPC_ERROR, INVALID_TIMESTAMP,
BUDGET_EXCEEDED, DELIVERY_INCOMPLETE. В health.json и /status отображается
число таких чатов (без имён, текста сообщений или секретов).

## Граница безопасных испытаний

Не отключаем Wi-Fi, не извлекаем и не размонтируем ArvectumSSD,
не разлогиниваем реальный MAX-аккаунт и не отправляем разрушительные
команды удаления. Mac mini обслуживает другие рабочие проекты.
Физические испытания с сетью, SSD, истечением токена и >24 часами простоя
проводить на отдельном тестовом стенде/аккаунтах.

Telegram Bot API не предоставляет idempotency token. Поэтому при
сомнительном сетевом исходе строгую exactly-once доставку гарантировать
невозможно: UNKNOWN требует отдельной сверки перед вмешательством.

- app/max_listener.py — перекрывающаяся пагинация и persisted catch-up warnings

Следующий этап работы: P1 Personal UX, приоритет — форматирование MAX elements.
Инфраструктурный gate с физическими обрывами остаётся открытым до
появления изолированной тестовой сессии и диска.

## Реальный тест launchd

Процесс MAX2TG на Mac mini был намеренно завершён сигналом SIGKILL
(не затрагивая другие службы, SSD или сетевой стек). launchd KeepAlive
поднял другой процесс; в журнале подтверждены MAX Authorized, catch-up
для пяти известных чатов и Telegram polling resumed. Сохранились 5 тем,
167 message mappings, 5 курсоров. SQLite quick_check = ok.
Все сбойные отправки проводились только в изолированных тестах.

Полная проверка: 361 passed. Предупреждения PTBDeprecationWarning
касаются старого представления RetryAfter и не являются падениями.
