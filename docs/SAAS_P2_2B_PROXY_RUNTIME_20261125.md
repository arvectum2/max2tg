# P2.2b — isolated client transport composition

Base: main 701a20b (merged PR #18). Offline candidate only; P2.2b remains open.

MaxClient accepts an optional session factory; its WebSocket loop and every existing HTTP session construction use that factory. The personal default calls the same aiohttp ClientSession as before, with unchanged options. The isolated factory uses explicit loopback proxy, trust_env=False, verified TLS and an eight-connection pool; it refuses other session options and creation after closure. This does not enable media: the broker still admits only the exact text endpoint. Dedicated isolated MAX factory reads the existing worker-owned secret, not the central registry. Telegram uses actual python-telegram-bot Bot with separate explicit HTTPXRequest transports for regular calls and getUpdates; both disable environment proxy/trust inheritance and require verified TLS. Initialization and shutdown are scoped to the loopback adapter. Trusted composition helpers connect these clients to IsolatedWorkerRuntime and managed external-only SharedGatewayRuntime with cancellation cleanup. No production entrypoint, no change to existing supervisor network guard.

The previous Docker TLS test now additionally drives the actual MaxClient binary handshake, synthetic authorization and one message RPC, and actual Telegram Bot getMe/getUpdates/sendMessage. The synthetic server verifies exact test identity and message and returns positive receipts; it sees exactly one handshake, auth, MAX send, Telegram getMe, getUpdates and sendMessage. Each role has its own channel; MAX secret mounted read-only only for MAX. Closing each broker listener causes the subsequent client request to fail rather than reach the upstream. All three runtime containers still network=none. Local tests also exercise environment proxy bypass prevention using a decoy loopback listener, invalid TLS and proxy options, closed factory, personal default and CONNECT parser boundary. The initial real MAX-class test exposed aiohttp's browser headers on CONNECT: the local adapter now permits only the four additional known browser header names, strips them by reconstructing the canonical request; strict broker parser unchanged. Reran successfully. No raw diagnostic headers retained.

867 tests passed (36 PTB deprecation warnings); targeted Ruff, preflight, original Spec Kit structural gate and extended Docker TLS test passed. All disposable labeled resources removed. No real accounts, live traffic, real credentials or personal deployment. Synthetic certificate and credentials are fixture-only. The transport test exercises client classes, not a complete supervised runtime using both actual client classes end-to-end. The composition helpers are not wired into the existing offline Docker supervisor. Production broker security/firewall, real DNS and TLS, broker lifecycle/health, unified API rate budget, dynamic volume provisioning, media/catch-up, authentication UX and field acceptance remain open. Existing CONNECT destination/SNI limitations from the prior design remain. Next: integrated supervised bridge with these actual transports on synthetic endpoints and explicit broker-loss/recovery; review hardened live-network policy before any separately authorized field test.
