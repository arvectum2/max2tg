# P2.2b — controlled network tunnel, offline proof

Base main 467524b (PR #17 merged). Offline candidate only; P2.2b remains open.

The proposed topology keeps each worker in a network=none container. A trusted broker exposes a dedicated private Unix socket per role/tenant; a loopback CONNECT adapter allows standard aiohttp and httpx proxy clients without directly attaching a worker to an external network. Exact destination authorities: max-text -> api.oneme.ru:443, telegram -> api.telegram.org:443. No arbitrary URL, port, media host or suffix wildcard, no direct fallback. The policy resolves once, rejects mixed or non-global DNS answers (including mapped/transition addresses), and dials the validated numeric address with AI_NUMERICHOST. It does not retry alternate addresses on failure. Broker handles bounded CONNECT headers, per-socket connection limit (8 default), timeouts and shutdown; no content logging. TLS remains end-to-end with the application client. Trusted host must own channel provisioning and enforce distinct socket mounts; a worker is not allowed to choose its role or another tenant's socket.

Evidence: 30 new tests cover destination/role rejection, private/loopback/link-local/transition addresses, mixed DNS response rejection before dial, numeric connection pinning, malformed CONNECT, tunnel I/O, connection cap and shutdown. Docker smoke uses three actual non-root network=none runtime containers and two disposable channel volumes; the broker dials a synthetic loopback TLS service via an injected connector (not the production DNS resolver). aiohttp WSS echo and httpx HTTPS succeed with explicitly trusted temporary test certificate. Cross-role/unknown/IP destinations are denied; default trust rejects the synthetic certificate. Certificate private key stays in broker fixture, client receives only public test cert. No real API traffic, secrets or accounts. All temporary resources removed. 863 tests, Ruff, runtime preflight and original Spec Kit structural gate pass; 36 existing PTB deprecation warnings. CI repeats the Docker test.

Limitations: CONNECT restricts the resolved destination IP and port, not the application-layer requests or encrypted SNI/Host inside an opaque tunnel. A compromised client could misuse an approved shared endpoint; this is not proof of complete egress containment. Production requires a hardened broker boundary, separate per-tenant socket mount permissions, outbound firewall/DNS restrictions, rate/byte quotas and threat-model review of shared hosting/route translation. Existing MAX/Telegram runtime clients have not yet been wired to these adapters. Broker and clients have not been tested against real service DNS, TLS or credentials. No live-network policy installed, existing supervisor network=none guard unchanged. Media hosts intentionally excluded from this text-first prototype; their own allowlist and validation require separate review. No account authentication or authorization flow, credential rotation, history/media parity or SaaS field acceptance.

Next: wire explicit proxy-only transport into isolated MAX/Telegram runtime (never personal default), add fail-closed transport tests and integrate broker lifecycle; then review trusted deployment/network firewall and separately authorize isolated live-account testing. Unified API budgets and durable RetryAfter still open.
