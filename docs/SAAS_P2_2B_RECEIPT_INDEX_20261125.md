# P2.2b — bounded incremental worker receipt projection

Base 0316ec8 (merged PR #36). Original roadmap acceptance unchanged. Shared worker only; personal listener and original personal TopicStore.set_message behavior unchanged. Existing repair scanned every SENT intent, reinserting evicted entries into the bounded 1000-per-chat JSON reply cache and fsyncing on each insertion. Added transactional receipt sequence migration to authoritative worker intent table, monotonically incremented by SQLite triggers when a row becomes SENT (including old pending intent becoming confirmed). Legacy SENT rows get migration order by rowid, not claimed historical confirmation order. Indexed recent per-chat query and pending-intent query. No deletion or replay of journal entries; terminal statuses preserved. In-memory watermark and binding identity skip unchanged history, rebuild recent projection on restart/replacement/new binding, select up to 1000 newest confirmed receipts per bound chat, apply oldest-to-newest with a single atomic JSON save. Retain existing conflict checks for projected entries and fail closed on persistence failure before advancing watermark. Full ledger still authoritative, cache remains bounded; this is not a full historical reply lookup or proof of detecting conflicts in evicted receipts. Trusted single-owner runtime and intact SQLite required; direct SQL mutation/rollback outside supported recovery gate not covered. Separate reverse ingress ledger startup repair remains unchanged.

Synthetic single-chat histories, exact same DB/cache implementation; old algorithm copied verbatim, save calls counted instead of executed to avoid thousands of fsyncs.
