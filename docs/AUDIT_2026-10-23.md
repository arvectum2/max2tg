# MAX2TG — аудит 23.10.2026

## Область проверки

Mac mini, MAX WebSocket, Telegram Bot API, форум-топики, импорт истории,
прямые исходящие MAX, дедупликация, вложения, URL, права на файлы,
поведение при отключении, конфигурация и журнал. Токены не раскрывались.

## Исправлено

1. FORWARD без собственного комментария теперь сохраняет MAX→TG ID и не
   повторяется при следующих событиях или импорте.
2. Импорт истории и новые события сериализуются по chat ID, устраняя гонку
   при параллельных путях пересылки.
3. Ошибки создания временного JSON не обрывают обработку сообщения;
   состояние хранится в памяти, повторная запись сохраняет его. Запись
   на диск атомарна и завершена fsync.
4. chat_ids изолированы по экземплярам MaxClient, а отсутствующие поля
   message.id / message.text нормализуются корректно.
5. При отключённом MAX RPC возвращается сразу, а ожидающие upload futures
   отменяются при потере WebSocket.
6. Вложения скачиваются с разрешённых HTTPS-доменов MAX/CDN; редиректы
   валидируются, потоковое скачивание ограничено 50 МБ.
7. Обычные информационные логи не содержат текст сообщений и реестр
   контактов; подробные payload доступны только в диагностике.

## Проверки

Полный pytest, отдельные тесты гонок, повторов, FORWARD, безопасности URL,
права на запись, ошибок в полях, compileall, pip check, git diff --check.
После установки требуется проверить соединение с MAX и Telegram, запись
состояния и отсутствие новых ошибок в логах.

## Остаточный риск

- Нет строгого exactly-once в Telegram API после таймаута. Пересылка длинных
  текстов при частичной ошибке потребует durable outbox.
- Автоматическая синхронизация пропущенных сообщений в уже известных
  чатах MAX по persisted checkpoint пока не реализована.
- Полное форматирование нативных элементов MAX не поддерживается.
- Медиа нестандартных CDN заблокированы до добавления проверенных хостов.
- Сквозные тесты на реальную отправку собеседнику и физическое отключение
  SSD не проводились, чтобы не создавать нежелательных внешних эффектов.
