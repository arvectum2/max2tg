# MAX2TG Personal UX v1.2 — P1.2, медиа (23.10.2026)

## Реализовано

### Фотоальбомы

Последовательные фотографии одного сообщения MAX объединяются в
Telegram sendMediaGroup партиями от 2 до 10 фото. 11 фотографий становятся
альбомом из 10 и отдельным фото. Подпись помещается к первому фото; остаток
длинной подписи уходит в ответном тексте без обрезания.

Каждый альбом — один вызов Telegram Bot API, но несколько Telegram
message_id. SQLite outbox содержит все подтверждённые ID (tg_ids), первый
остаётся основным MAX→TG mapping. P0.3 delete может удалить каждый
элемент альбома, не затрагивая посторонние сообщения. Для существующих
SQLite-баз добавляется tg_ids без удаления данных. Сбойные вызовы
отмечаются RETRY/UNKNOWN по прежним правилам, никакого слепого повтора
после сетевого таймаута. Вложенные в zip байты альбома хранятся до полной
доставки и позволяют повторить отправку при истечении URL MAX.

При ошибке скачивания одной фотографии используется поэлементный
fallback с явным обозначением недоступной картинки.

### Оригинальные медиа

- VIDEO: если имеется прямая ссылка на скачиваемое видео, передаётся
  оригинальный файл через sendVideo; если он недоступен, миниатюра
  отправляется с ясной подписью «только превью», иначе — текстовая
  отметка. Никакие неподтверждённые opcode MAX для получения видео
  не вызываются. HLS playlists/внешний player не скачиваются как видео.
- FILE: поддержаны поля MAX history fileUrl/fileName/fileSize, а также
  url/name/size. Исходное имя файла очищается от управляющих символов.
  PNG/JPEG передаются как фото, MP4 как видео, MP3/M4A и другие типы
  аудио как sendAudio. GIF, WEBP, BMP, MOV, MKV/AVI и другие файлы
  сохраняются в качестве оригинальных документов вместо попыток
  отправить их в неподдерживаемом формате.
- AUDIO/UNSUPPORTED audioId: ссылка на оригинальную запись может быть
  получена существующим download_audio_url(user-session); передаётся
  как голосовое, если доступно, иначе понятная текстовая отметка.
- PHOTO без доступной ссылки, FILE без возможности скачивания и VIDEO
  без исходника теперь не исчезают молча: остаётся объясняющее
  сообщение в соответствующей Telegram-теме.
- Исправлена геопозиция с нулевыми широтой/долготой.

### Защита доставки

Родительское MAX-сообщение помечается доставленным только после
завершения всех вложений и всех частей подписей. Успех первого файла не
маскирует ошибку второго. Отдельные Telegram сообщения и медиа-группы
записываются в ту же persistent outbox; после рестарта части с
подтверждёнными ID не отправляются повторно.

Загрузка медиа осуществляется только через прежний HTTPS/CDN allowlist
и с действующим лимитом размера. Вложенные URL и токены MAX не
записываются в информационные логи.

## Известные границы

- В пользовательском WebSocket MAX доступ к оригинальным видео без
  прямой ссылки остаётся ограниченным. Не используем сомнительный
  GET_VIDEO_URL opcode 83 — он конфликтует с номером CALL_LEAVE в
  неофициальной документации.
- Telegram Bot API имеет лимиты размера, форматов и до 10 медиа в одном
  альбоме. Альбомы суммарно больше 45 МБ отправляются поэлементно.
- Без отдельного тестового аккаунта не выполнялись настоящие загрузки
  больших файлов и видео в рабочие чаты. Unit/regression тесты —
  симуляции Bot API и payload пользователя.
