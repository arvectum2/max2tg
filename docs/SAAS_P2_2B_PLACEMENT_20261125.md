# P2.2b — reproducible held Linux placement package

Base main adc2513 (merged PR #30). The original roadmap and acceptance criteria remain unchanged. This package is intentionally NOT a runnable bridge or production launcher.

`python3 scripts/saas-placement-plan.py --deployment <24-hex-id> --image <sha256:local-image-id> --data /srv/max2tg/data --backup /srv/max2tg/backup --keys /run/max2tg-keys --sid <24-hex-sid> --sid <24-hex-sid>` renders deterministic Compose JSON (stdout only). Explicit 1–100 distinct tenant IDs, canonical disjoint roots, exact pinned image ID. `placement-only` profile, pull never, all containers network none, command exits 78 instead of running any messenger code. No automatic start/restart, no Docker socket, no live credentials. Worker mounts own state and dedicated channel RW, own envelope and key and network channel RO. Gateway mounts central registry and per-tenant channels RW, bot envelope/key and network RO. Broker mounts only per-tenant network channels and Telegram channel RW; no registry/secret/key. Backup root not mounted into any runtime. Root filesystem RO, all capabilities dropped, no-new-privileges, nonroot UID/GID 65532, memory 256 MiB/CPU 0.5/pids 64 provisional, core limit zero, bounded local logs. No host directory auto-creation. No build, no personal compose changes. Host provisioning and independent key custody remain separate.

`validate_bind_sources` rejects missing/nonprivate directories, symlinks, overlapping or same-inode mount sources. `verify_stopped_container` compares trusted generated role spec to actual Docker inspect including name, image, labels, command, created state, network, mount sources and flags, UID, bounds, restart, privileges and logging. This is a selected configuration check, not comprehensive host attestation; run local storage preflight separately and independently verify backing storage, namespace, actual runtime IDs, root ownership, host security. No untrusted readiness override. Result always includes live_launch_authorized=false. Do not use Compose up to start the bridge; held containers are only placement rehearsal. A real restricted broker and production entrypoint still require implementation and acceptance.

Evidence: `python3 scripts/test-placement-plan.py --image max2tg:encrypted-overlay` renders JSON, creates only four stopped containers with 14 empty private host bind source directories, validates Compose, checks real Docker inspect, removes only synthetic labeled containers and temporary directories. No runtime starts or external network calls. Deterministic tests cover identity/roots, wrong worker key, extra Docker socket, command/image drift, privilege/network, log/core limits, running container, missing evidence, private source validation and symlink rejection. 917 full tests passed, 45 existing PTB warnings, targeted Ruff, runtime preflight and Spec Kit structural gate pass. Docker placement check passed locally, added to fresh-image CI. Local candidate image from previous validated overlay; no new full build claim. Personal bridge unchanged. No LUKS provisioning or firewall modification.

Remaining: real deployment runtime entrypoints, protected host and independent key/anchor custody, actual firewall enforcement and namespace evidence, coordinated restore gate at deployment boundary, two real independent MAX accounts and separate test bot/forums. Keep P2.2b/P2.2c open. Primary next step: prepare an explicit offline acceptance harness for the real runtime entrypoints with the planned exact bind placement and no live network, rather than another declarative readiness report. Actual live host provisioning/account acceptance requires separate prerequisites.
