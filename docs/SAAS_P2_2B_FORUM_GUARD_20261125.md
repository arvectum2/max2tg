# P2.2b — periodic forum verification and membership-event guard

Dependent on PR #15 (24fa9d4). Offline managed gateway only; no production activation.

Reuses onboarding's exact forum verification: private forum, owner creator, bot administrator with topic rights, two members, pinned bot identity. Positive evidence expires after 30 seconds, measured from the beginning of the multi-call verification; no lease survives gateway restart. Timeout (8 seconds per check) or API error holds delivery; retries after 5 seconds in this test prototype. Both ingress and egress recheck the local evidence immediately before claiming a send. Unattempted RECEIVED/QUEUED items remain durable; temporarily held sessions are excluded from ready batches to avoid starving other tenants. Existing SENT/ACKED/UNKNOWN remain unchanged. Pending revoked items become BLOCKED when drained. Topic creation is also gated. Managed listeners close during verification hold; lifecycle reports active but not ready, so no new launches or crash-budget reset. Existing running worker is not force-stopped during temporary hold.

Trusted polling requests chat_member and my_chat_member updates. Membership and relevant service events invalidate cached evidence before the polling offset is committed. Definitive third-party join, owner demotion/departure, bot loss of admin/topic permissions or group migration revokes the onboarding and disables routing; no automatic restoration on subsequent valid snapshot. Other membership changes require fresh evidence. Definitive policy mismatch during periodic verification similarly revokes. Revocation is durable before acknowledging the event. No changes to legacy/personal routing policy.

Verification: 830 tests passed, targeted Ruff, runtime preflight and unchanged Spec Kit source gate. Three new tests cover lease expiry and transport hold with queue preservation, resumption, confirmed policy violation and terminal revocation, membership-event invalidation, restart without positive lease, explicit join revocation. Integrated three-container smoke replaces operator revoke with a synthetic trusted membership event; affected worker stops while the other delivers, existing UNKNOWN remains quarantined. Disposable resources removed. Existing 33 PTB warnings. No live Telegram/MAX operation.

Limitations: periodic multi-call snapshots and received events are not atomic with delivery. A membership change may occur before its event arrives, between checks, or after a send is already in flight. No guarantee of zero exposure or recall of prior messages. The synthetic event is injected at the guard in the Docker test; unit tests exercise polling invalidation. API Forbidden and other incomplete responses hold rather than conclusively prove revocation. New owner messages can still be durably admitted during a temporary hold; no delivery until verified. Chosen TTL/retry/timeout are provisional, not production SLA. Sequential verification and rate limits need bounded concurrency, backoff and load testing at scale. No real account tests, live network policy, dynamic volumes, secret rotation, catch-up/media parity or public authorization flow. Next: rate-limit-aware scalable verification and controlled real-network deployment design; retain P2.2b/P2.2c acceptance gates.
