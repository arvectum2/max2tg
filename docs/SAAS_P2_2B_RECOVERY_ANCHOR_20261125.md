# P2.2b — offline recovery manifest and independent continuity anchor

Base main f0f3fb8 (PR #21 merged). Offline recovery verification only; no automated restore or production enablement.

RecoveryAnchor records a complete explicit snapshot member set with SHA-256 file digests, checks standalone SQLite copies with quick_check, rejects WAL/SHM/journal sidecars, symlinks, unexpected members, non-private files and mixed-generation data. Epoch and generation stored atomically in an independent private directory that must not be included in restored volumes. Mark dirty before any later external effects; dirty anchors refuse verification even of latest backup. Clearing dirty requires an explicit trusted reconciliation assertion, not a mere matching digest. Membership changes need a separate provisioning procedure. Verify returns structural_only; external message delivery is not proved by a database hash. Tests show older and mixed snapshots rejected, missing membership and unsafe paths rejected, dirty/missing anchor blocked. Initial test expected a different exception for changed membership; corrected to test both rejection paths. 875 full tests, Ruff, runtime preflight and original Spec Kit structural gate pass.

Limits: trusted single offline operator must actually stop all writers and hold appropriate locks; quiescent/reconciled are caller assertions, not attestations. Capture does not create coordinated copies itself; copies must be made under stopped writers. No automatic start/restore or runtime integration; no production backups modified. Both anchor and all copies rolled back together cannot be detected by this component. Need independent durable anchor retention and runtime write fence, actual coordinated backup tool and tested automatic dependency restart before live acceptance. Never replay UNKNOWN. Personal alert fix is separate PR #22, not part of this change.
