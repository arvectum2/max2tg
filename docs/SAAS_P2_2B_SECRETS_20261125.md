# P2.2b — external worker MAX secrets

Base: PR #10, 9897c41. Offline development only. P2.2b remains open.

New shared capsules can be configured using `configure_external_shared(sid, forum)` with routing metadata only. The gateway never receives a MAX credential or secret file path for this operation. The additive `credential_mode` field preserves legacy dedicated/shared behavior. External configuration is immutable with respect to the forum, refuses existing legacy files, and cannot be replaced by legacy configuration. Activation is a trusted operator assertion, not proof that the worker has a valid credential. Existing sessions are not migrated or deleted. An external-only gateway checks known capsule rows for legacy credential files or configured legacy mode and refuses active capsules without dedicated channels. This startup check is not a general filesystem secret scanner or a protection against a privileged operator modifying the registry later.

`worker_secrets.py` provisions a session-bound MAX-only JSON file in a private directory. Atomic no-overwrite publication, fsync, no-follow opens, file ownership, mode, size, link count and schema checks protect the supported provisioning/read paths. Duplicate installation and wrong session or extra secret fields fail closed. The MAX client factory loads the local credential without environment inheritance, argv or logging; live authentication is not invoked in this slice. Mount worker secret volumes read-only in normal runtime. Host provisioning must be trusted; rotation, encryption at rest, credential revocation and recovery of interrupted provisioning remain separate work.

The Docker acceptance fixture uses seven disposable volumes: central registry, two channel volumes, two state volumes and two MAX-secret volumes. The gateway mounts only registry and channels; each worker mounts only its own state, channel and read-only secret. All three non-root runtime containers have network disabled and no capabilities. Gateway scans the synthetic registry for test token bytes, checks absence of credential files and secret mounts; worker factory verifies its own credential, rejects writable secret mount, and completes both text routes. Two outgoing messages and two incoming ACKs, no duplicates. All disposable resources removed. No real secrets, accounts, or deployment touched.

817 unit/contract tests passed; targeted Ruff, runtime preflight and unchanged Spec Kit gate passed. Actual Docker test on Mac mini passed. Existing 33 PTB deprecation warnings. Previous PR #10 must pass CI before merging this dependent slice. No production shared worker entrypoint, orchestrator, live MAX authorization, history, media or field acceptance yet.
