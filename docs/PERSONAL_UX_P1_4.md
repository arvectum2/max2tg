# MAX2TG Personal UX P1.4 — настройки отдельных чатов

Дата: 23.10.2026. Личная версия на Mac mini.

## Telegram UX

Открыть /chatsettings непосредственно внутри привязанной MAX-темы либо
через «Мои чаты» → соответствующий чат → «Настройки чата».
Доступ администратору супергруппы; пользователь не вводит MAX chat ID.

Доступные настройки:
- sync (по умолчанию true): поставить всю синхронизацию MAX↔Telegram
  на паузу. При паузе MAX live events не ставятся в очередь; уже
  находившиеся в SQLite RETRY задачи не исполняются до возобновления,
  изменения/реакции также не применяются. Telegram→MAX текст, медиа,
  правки и реакции блокируются. При возобновлении мост пытается
  догрузить пропущенное по сохранённому cursor, если история MAX
  позволяет. Никаких гарантий восстановления после >24 часов нет.
- mute (false): disable_notification=true для отправок бота
  в конкретную Telegram-тему, включая media group. Не меняет системные
  настройки уведомлений пользователя или MAX.
- media (true): если выключено, MAX→TG передаёт исходный текст и
  явную текстовую отметку о количестве/типах вложений без скачивания;
  отправка TG→MAX медиа блокируется с объяснением. Тексты по-прежнему
  передаются.
- history_depth (общая настройка/0/20/50/100): сколько сообщений
  автоматически импортировать при создании новой темы. Ручная
  /history остаётся порционной по 20 и не зависит от этого параметра.
- archived (false): исключить MAX-чат из активного списка управления.
  Отдельное «Архивные чаты» позволяет вернуть его обратно. Сам Telegram-
  топик не скрывается, не удаляется и при включённом sync работает обычно.
- title_sync (false): синхронизировать название Telegram-темы с
  названием MAX при поступлении сообщения; при активации попробовать
  немедленно обновить. Выключено по умолчанию для защиты пользовательских
  переименований. Смена аватара Telegram forum topic на произвольную
  фотографию официальным Bot API не поддерживается; /intro обновляет
  карточку с фото и может быть использована вручную.

## Реализация

- app/chat_preferences.py — валидируемые значения с индивидуальным
  хранением в ui.chat_preferences внутри topics.json. Настройки
  переживают restart; старые темы получают прежние значения по умолчанию.
- app/chat_settings_ui.py — экран и кнопки с проверкой Telegram
  SUPERGROUP и администратора.
- app/max_listener.py и app/message_sync.py — запреты sync и media на
  MAX→TG, безопасная повторная сверка, настройки истории.
- app/tg_handler.py — запреты TG→MAX, архивный список и меню.
- app/tg_sender.py — индивидуальные disable_notification, opt-in
  синхронизация имени; проверены обычные сообщения и альбомы.
- app/history_ui.py — при паузе ручной импорт истории запрещён;
  интерфейс поиска остаётся доступным и только читает данные.
- TopicStore.remove очищает индивидуальные предпочтения удалённой темы.
- Общий global history_import_limit сохранён для чатов без override.

## Известные ограничения

- Архивация — фильтр списка MAX2TG, не Telegram Archive и не
  системная операция MAX.
- Пропущенные во время паузы события восстанавливаются из доступной
  MAX-истории, но при её обрезании полнота не гарантирована. При
  неудобоваримой timestamp-пагинации курсор не перемещается и
  оператор видит HISTORY_GAP.
- Изменение политики медиа во время уже начатой частичной доставки
  может оставить UNKNOWN/RETRY часть для ручной сверки: мост не
  дублирует неопределённые Telegram API вызовы.
- Для реальной смены MAX-аватарки использовать существующую /intro
  вместо неподдерживаемой попытки изменить иконку форум-темы.
- Физические испытания P0.5b на отдельном аккаунте остаются открыты.

## Приёмка

tests/test_chat_preferences.py проверяет значения по умолчанию,
персистентность, независимость чатов, защиту от неверных настроек,
pause/resume, MAX и TG маршруты, медиа, уведомления, альбомы,
архив, включение title sync и права администратора. Весь pytest,
compileall, pip check и git diff --check.
До установки резервное копирование topics.json и SQLite; после —
launchd/MAX/TG/health/сопоставления и целостность SQLite.
